# 2026-11-09: L3 pattern spotting (conditions and checks)

Three one-line problems, each answered with pattern + tool + why.

Key points:
- Sum of positive orders: accumulator. filter keeps finite numbers > 0, then reduce adds them. The result is a number, so the start value and the "nothing" value are 0.
- Every setting is a non-empty string: an "every" check. All values must pass, so stop at the first failure. Check the type AND the value: `typeof v === 'string' && v !== ''`.
- `{}` gives true for an every check: no value breaks the rule, same as `[].every(...)`.
- First non-digit index: a search that needs the index, so `for (let i ...)` and return early. Not found is -1 because the return type is an index.
- "Not a digit" is `ch < '0' || ch > '9'`. With `&&` it can never be true.
- `reduce` on an empty array with no start value throws a TypeError.

```js
const sumPositive = a => !Array.isArray(a) ? 0
  : a.filter(x => Number.isFinite(x) && x > 0).reduce((sum, x) => sum + x, 0);

const allNonEmptyStrings = s =>
  typeof s === 'object' && s !== null && !Array.isArray(s) &&
  Object.values(s).every(v => typeof v === 'string' && v !== '');

function firstNonDigitIndex(input) {
  if (typeof input !== 'string') return -1;
  for (let i = 0; i < input.length; i++) {
    if (input[i] < '0' || input[i] > '9') return i;
  }
  return -1;
}
```

What went wrong:
- Said the sum's empty value is `[]`; it's `0`.
- Checked only `v !== ''`, so `{ size: 12 }` would pass.
- Listed `{}` as an edge case without deciding its output.

Flashcards:
- `[].every(fn)`? → `true`.
- `[].reduce((a, b) => a + b)`? → TypeError; pass `0` as the start value.
- Need the index while searching? → `for (let i ...)` or `findIndex`.
