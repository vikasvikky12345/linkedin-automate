## Topic 1: Variables, scope, hoisting, TDZ (6.5/10, then two revisions: 3.8/5, 3.67/5)

### Key points
- `var` is function-scoped and hoisted with the value `undefined`. It ignores blocks, even `if (false) { var x }`.
- `let` and `const` are block-scoped and hoisted too, but sit in the Temporal Dead Zone until their line runs. Touching them earlier throws `ReferenceError: Cannot access 'x' before initialization`.
- A local declaration anywhere in a scope shadows the outer variable from the first line of that scope.
- "x is not defined" means no declaration exists anywhere up the scope chain. If a `let`/`const` exists in an enclosing scope, you get the TDZ error instead.
- Assigning without `let`/`const` creates an implicit global (and throws in strict mode and in modules).
- After an uncaught error, nothing below it runs. Stop predicting output there.
- Two techniques that fixed most of my mistakes: "rewrite before you read" (move every `var` to the top without its value) and "walk up, never down" (look up the scope chain only).

### Code
```js
var x = 'outer';
function f() {
  console.log(x); // undefined, not 'outer'
  if (false) { var x = 'inner'; }
}
f();
```

```js
let y = 1;
function g() {
  console.log(y); // ReferenceError (TDZ), not 1
  let y = 2;
}
g();
```

## Topic 2: Data types, coercion, == vs ===, typeof (6.5/10)

### Key points
- 7 primitives (string, number, bigint, boolean, undefined, symbol, null) plus objects.
- `===` compares without coercion. `==` coerces, with special rules: `null == undefined` is true, and `null` is loosely equal to nothing else.
- `null == 0` is false, but `null >= 0` is true, because relational operators convert to numbers.
- `Object.is` differs from `===` in exactly two cases, in opposite directions: `NaN` (=== false, Object.is true) and `0` vs `-0` (=== true, Object.is false).
- `typeof null` is `'object'` (old bug), `typeof function(){}` is `'function'`, and `typeof typeof x` is always `'string'`.
- Falsy values: `false, 0, -0, 0n, '', null, undefined, NaN`. Everything else is truthy, including `[]`, `{}` and `'0'`.

### Code
```js
console.log(null == 0);  // false
console.log(null >= 0);  // true
console.log(NaN === NaN);         // false
console.log(Object.is(NaN, NaN)); // true
console.log(0 === -0);            // true
console.log(Object.is(0, -0));    // false
```

```js
console.log([] + {});          // '[object Object]'
console.log(typeof typeof 1);  // 'string'
```

## Flashcards
1. Q: What does `typeof x` do if `let x` is declared later in the same scope? A: Throws the TDZ ReferenceError. `typeof` is only safe for undeclared names.
2. Q: `null == 0`? A: false. `x == null` matches only null and undefined.
3. Q: Two cases where `Object.is` and `===` disagree? A: `NaN, NaN` and `0, -0`.
